# Progress Tracking — How It Works

> Copy this whole folder to `docs/progress/` in the repo during Stage 00 (task S00-T12). From then on these files are the single answer to: **which stage is running, what is done, what is in progress, what is blocked, and what we left out on purpose.**

## The files

| File | Answers | Updated |
| --- | --- | --- |
| `STATUS.md` | Where are we right now? Current phase, stage(s), task(s), overall %, blockers, upcoming decisions, milestones | Every PR that changes a task's status (the % columns are generated by `npm run progress`) |
| `stages/stage-NN.md` | What exactly is done / in progress / left in this stage? One row per task with status, owner, PR, tests | Created when a stage starts; updated in the same PR as the code |
| `DEFERRED.md` | What did we **leave out on purpose**, why, who decided, and when do we come back to it? | Whenever something in the plan is not built now |
| `SESSION-LOG.md` | What happened in each working session (human or AI)? So the next session never starts cold | End of every working session |

Plan decisions stay in `docs/plan/09-decisions-and-risks.md` and `docs/adr/`. These files track **execution**, not design.

## Task IDs and statuses

- Task ID: `S<stage>-T<nn>` — e.g. `S04-T09` = Stage 04, task 9. Tasks come from the stage file's work breakdown (§3); split an item into several tasks if it needs more than one PR (< 400 changed lines each).
- Deferred ID: `DEF-<nnn>`.

| Task status | Meaning |
| --- | --- |
| `TODO` | Not started |
| `DOING` | Someone (or an AI session) is working on it now |
| `REVIEW` | PR open, waiting for human review |
| `DONE` | Merged, tests green |
| `BLOCKED` | Can't continue — reason and blocker ID in Notes; also listed in `STATUS.md` → Blockers |
| `DEFERRED` | Left out **on purpose** — must have a `DEF-…` row in `DEFERRED.md` |
| `DROPPED` | No longer needed — reason in Notes (and an ADR if it changes the plan) |

| Stage status | Meaning |
| --- | --- |
| `NOT_STARTED` | No task started |
| `IN_PROGRESS` | At least one task started |
| `BLOCKED` | The stage can't progress until a blocker is cleared |
| `DONE` | Every task is `DONE`, `DEFERRED` or `DROPPED`; every Definition-of-Done box is ticked; mandatory tests green |

**Progress %** of a stage = `DONE ÷ (all tasks − DROPPED − DEFERRED)`. Deferred tasks are shown separately so leaving things out never looks like finishing them.

## Rules (also in `AGENTS.md`)

1. **Start of a session:** read `STATUS.md`, the current `stages/stage-NN.md` and the last 3 entries of `SESSION-LOG.md`.
2. **Start of a stage:** copy `stage-progress-template.md` to `stages/stage-NN.md`, list every work-breakdown item as tasks, copy the Definition of Done and mandatory tests, set the stage to `IN_PROGRESS` in `STATUS.md`.
3. **Every PR** updates the status of its task(s) in the stage file — in the same PR as the code. The PR template has a checkbox for it.
4. **Nothing is silently skipped.** If something in the plan won't be built now, add a `DEF-…` row before the PR merges and mark the task `DEFERRED`.
5. **End of a session:** add a `SESSION-LOG.md` entry (goal, done, not done and why, PR, tests run, next step).
6. **A stage is `DONE`** only by the rule above, confirmed by a human reviewer.
7. **CI check:** `npm run progress -- --check` fails if the generated numbers in `STATUS.md` are out of date or a `DEFERRED` task has no `DEF-…` row.

## `npm run progress` (built in S00-T12)

A small script that:
- reads the task tables in `stages/*.md`,
- counts statuses per stage,
- rewrites the generated block in `STATUS.md` (between `<!-- progress:start -->` and `<!-- progress:end -->`): per-stage done/total, deferred count, %, and overall %,
- with `--check`: changes nothing, exits non-zero if the block is stale or a `DEFERRED` task has no matching `DEF-…` row in `DEFERRED.md`.
